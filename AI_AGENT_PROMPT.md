# ТЗ для разработки ИИ-агентом: Веб-сервис предзаказа фермерского мяса "Мясной Пул Таврическое"

## Контекст и цель проекта
Проект создается для автоматизации сбыта фермерского мяса (КРС, герефорды) напрямую конечным потребителям в Таврическом районе Омской области. 
**Бизнес-модель:** Продажа мяса "наборами/коробками по 12-15 кг" до момента физического забоя скота (краудфандинг/пул-система). Как только набирается нужное число броней на тушу (например, 15 коробок по ~13 кг на тушу в 200 кг) — фиксируется дата забоя.
**Цель для агента:** Создать легковесный, современный и быстрый веб-сервис (Landing Page + админка/CRM для учета лидов), готовый к деплою на **Railway**.

---

## Архитектура и Стек технологий
Стек должен быть максимально простым для деплоя на Railway, быстрым в сборке и надежным:
* **Backend:** Node.js (Express) или Fastify, либо полностью Fullstack-фреймворк: **Next.js (App Router)** / **Remix** / **SvelteKit** (на выбор ИИ-агента для монолитного деплоя). Рекомендуется Next.js / Node.js + Express.
* **Database:** SQLite (локальный файл в директории или с подключением через Prisma/Drizzle) или PostgreSQL (если база создается прямо на Railway). Для старта проще использовать **SQLite** (с volume в Railway) или **PostgreSQL** (Railway Addon).
* **Frontend:** Tailwind CSS, TypeScript, Shadcn UI / Radix (для аккуратного интерфейса).
* **Специфика Railway:** Наличие `Dockerfile` или корректно настроенных скриптов сборки (`package.json` -> `start`, `build`).

## Функциональные требования

### 1. Публичная часть (Landing Page для трафика из ВК/ОК/Директ)
* **Первый экран (Hero):** 
  * Сильный оффер: "Настоящая домашняя говядина (герефорды) в Таврическом с доставкой к дому".
  * Статус текущего пула: Индикатор/Progress Bar (Например: "Собрано 7 из 15 броней на Бычка №1. Осталось 8 коробок").
  * Кнопка "Забронировать набор (без предоплаты)".
* **Блок калькулятора / состава коробки:**
  * Четкое описание семейного набора (12-13 кг): сколько мякоти, стейков, ребер, супового набора. Фиксированная или ориентировочная цена за кг и за коробку.
* **Форма заказа (Лид-форма):**
  * Поля: Имя, Телефон (маска ввода), Населенный пункт (Таврическое / деревни района / Омск), Количество коробок.
  * Важно: **Никаких онлайн-оплат!** Только фиксация брони. После успешной отправки — экран "Спасибо, мы свяжемся для подтверждения за 3 дня до забоя".
* **Блок доверия:** Фото реальных животных на подворье, описание условий откорма (зерно, сено, 1.5 года).

### 2. Панель управления (Админка/CRM для фермера)
Доступ по секретному роуту (например, `/admin-dashboard`) с базовой авторизацией (хотя бы по переменной окружения `ADMIN_PASSWORD`).
* **Список заявок:** Сортировка по дате, статусу (Новый, Подтвержден, Отказ, Доставлено).
* **Управление пулами (тушами):** Возможность закрыть текущий пул (тушу) и открыть сбор на следующую голову (всего 3 головы).
* **Сводная статистика:** Общий забронированный вес, сумма потенциальной выручки, количество свободных мест.

## Интеграции и Уведомления
* **Telegram-бот / Уведомления:** При поступлении новой брони, скрипт должен отправлять фермеру мгновенное сообщение в Telegram (через Telegram Bot API) с деталями заказа: имя, телефон, объем.

## Пошаговый план реализации для ИИ-агента

### Этап 1: Инициализация и Среда
1. Создать структуру проекта. Настроить конфигурационные файлы (`.gitignore`, `README.md`, `tsconfig.json`).
2. Настроить ORM (Prisma/Drizzle) и схему базы данных (таблицы `Orders`, `Pools`, `Settings`).
3. Подготовить конфигурацию для деплоя на Railway (`nixpacks.toml` или `Dockerfile` при необходимости, настроить считывание `PORT` из `process.env`).

### Этап 2: Бэкенд и Логика Пулов
1. Написать API эндпоинты для:
   * Получения данных о текущем активном пуле (процент заполнения).
   * Создания нового заказа (с валидацией телефона и отправкой алерта в Telegram).
   * Админских действий (смена статуса заказа, создание нового пула).

### Этап 3: Фронтенд и Интерфейс
1. Реализовать адаптивный Landing Page по сетке Tailwind. Особое внимание уделить мобильной версии (95% трафика из ВК/ОК заходят со смартфонов).
2. Написать интерактивный прогресс-бар, динамически обновляющийся из БД.
3. Создать страницу админки с таблицей лидов и кнопками экспорта/обработки.

### Этап 4: Подготовка к деплою
1. Убедиться, что все секреты (Токен ТГ-бота, Админ-пароль, строка подключения к БД) берутся из `process.env`.
2. Проверить build-скрипт на отсутствие ошибок компиляции TypeScript.
